# Shared App Maker acceptance contract — v0.1 (PROPOSED)

One binding target for future builder self-audit and independent auditor, once owner validates pilot scope. The existing browser demo is **not** evidence of any production criterion. The core must never bypass source permissions or edit posted financial entries. An auditor may introduce a new blocker beyond this contract only for material security, financial integrity, privacy, data loss, unrecoverable correctness or severe operational failure.

| Milestone | Required behavior | Objective verification / fail condition | Evidence |
|---|---|---|---|
| F0 Shared foundation | One backend runtime, typed capability schema and cloud/local config contracts; DEMO remains isolated. | Schema validation rejects unregistered tool and unknown field. Same unit suite on local and cloud profiles. | source SHA, schema tests, lint/typecheck. |
| F1 Tenant identity/policy/audit | Tenant isolation, operator vs tenant roles, persistent redacted audit. | Cross-tenant read, report, cache and credential requests denied; revoked user fails; audit is durable on restart. | negative integration tests and DB evidence. |
| F2 Telegram private text | Real signed/secret-verified bot ingress, paired identity, chat-to-tenant routing and revoke. | Unpaired chat, replayed update, invalid webhook and group request denied; no test token in repo. | sandbox bot E2E, security logs redacted. |
| F3 Drive read-only | Scoped OAuth and allowlisted Sheet/XLSX retrieval, per-user resource check, provenance. | Unauthorized/unshared file refused; amended/revoked permission rechecked; ambiguous currency/header does not fabricate totals. | test Workspace E2E with non-sensitive files. |
| F4 Client REST read-only | Versioned route/response mapping, TLS/host allowlist, server-side source permission. | SSRF, unregistered endpoint, cross-tenant auth, invalid schema and redirect blocked. No generic SQL. | test API E2E and mock negative tests. |
| F5 Source-grounded AI | Allowed typed tool calls, source-aware answer, model provider abstraction; deterministic financial amounts. | Prompt injection cannot access other source or override policy; source outage yields explicit error, not invented data. | adversarial/e2e tests, provider test run. |
| F6 Reports | Source-linked CSV then approved native XLSX/PDF, report access checked at download. | Unauthorized/expired link fails; money, period, currency, row coverage and source revisions match records. | exact-filename artifact checks and integration tests. |
| F7 Voice notes | STT/optional TTS passes through same auth and audit. | Unauthorized voice command has same denial as text; supported Dari test phrases measured with owner. | voice test cases, cost/privacy evaluation. |
| F8 Dual deployment | Same core/version validated in cloud and local container; secure outbound bridge for local-only source if needed. | No public unauthenticated local port; backup/restore tested; offline state cannot pretend Telegram/Drive works. | reproducible deployment/rollback logs. |
| F9 Permissioned writes (deferred) | Typed source-domain endpoint + approval + audit + idempotency. | Balanced entries, no posted-record rewrite, duplicate/replay safe, reversal policy, approved actor enforced by source system. | domain integration and adversarial finance tests. |

**Demo gate (D-01 to D-10):** `docs/00-demo/DEMO_ACCEPTANCE.md`; owner visual walkthrough outstanding. **Production gate:** F0–F8 individually pass at exact SHAs and with real sanctioned test accounts; F9 has a separate release gate and cannot be inferred from read-only pilot. All missing credentials or official policies are feature-specific blockers in `OPEN_ITEMS.md`. No green CI claim without actual CI evidence.
