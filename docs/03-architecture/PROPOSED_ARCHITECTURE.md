### Reuse boundary
OS AI Core is shared application code and capability execution interface. Each customer supplies a *connector manifest* specifying permitted capabilities, trusted API endpoint or approved OAuth scope, source schema/metadata, tenant mapping, data classification and action confirmation. Multiple customers never share credentials or authorization contexts. Connectors cannot simply expose arbitrary SQL or all Drive files to an LLM.

### Real Google Drive path (future)
Connect via customer-approved OAuth / service-account sharing as appropriate to ownership and policies. Discover only allowed files, parse Sheets/XLSX deterministically, retain source ID, modification time, sheet/range and formula/value policy, enforce document ACLs at retrieval and at reply. Cache/index only with an approved data-retention policy. A document reference is not proof a user has access.

### Real client-ERP path (future)
Use authenticated versioned APIs to reach existing **domain services**, not direct generic DB writes. For accounting: double-entry balance, immutable posted journal entries, reversible corrections, decimal arithmetic, idempotency, approvals and audit are enforced in the ERP regardless of AI reasoning. For offline customer-hosted systems, a mutually authenticated outbound connector can be evaluated; never silently open an unauthenticated port on a PC.

### Telegram channel (future)
Bot tokens in secret storage; receive updates via secured webhook or vetted polling; pair private Telegram user IDs with a verified company user through short-lived one-time challenge; require reauthentication or approval in the company's trusted UI for sensitive writes. Treat group messages, forwarding, device compromise and source document exfiltration as threats. Avoid sending full payroll/customer records or financial statements to Telegram without explicit policy.

### Voice and report (future)
Voice notes: STT → same authorization/tool pipeline → optional TTS. Real-time voice conversation is a separate protocol/cost/UX milestone. Finance and spreadsheet arithmetic belongs in validated deterministic code, never exclusively in an LLM. Native XLSX/PDF reports must preserve source identifiers, reporting date, permissions and provenance, and should be generated by vetted export services.

### Core data model draft
Tenant, Deployment, UserLink, RoleGrant, ConnectorInstance, CredentialReference, SourceResource, CapabilityDefinition, ConversationSession, ToolInvocation, ApprovalRequest, ReportArtifact, AuditEvent. These are **candidate** entities; actual models and retention depend on the owner decisions in OPEN_ITEMS.md.

### Demo implementation difference
The current code only uses static fixtures with a small keyword router, not an LLM; a browser Telegram simulation, not a bot; no persistent identity or network connector. It validates the user journey, not production architecture/security.
